## What this PR does

Send MIDI Beat Clock (24 F8 per quarter note), transport and Song Position Pointer to selected ports. Setup › MIDI › MIDI Beat Clock stores a signed offset per named port on this computer. The scheduler shares audio presentation timing, compensates device and mixer delay, and preserves tick count across gaps in output timing.

## Hardware status

Windows → TASCAM Model 12 USB MIDI → DIN → Roland UM-ONE verified 20/20 idle starts, 5/5 minimized starts and 20/20 loop-end stops at 480 frames. The −200-sample setting advanced sustained F8 arrivals by 4.268/4.071 ms at 120/180 BPM. Timestamp-gap repayment was verified with a deterministic receiver. The 256-frame physical stop case, acoustic alignment and physical output-port removal/recovery remain open. The opt-in OS loopback command is `cargo test -p soundcraft-playback --lib beat_clock_reaches_a_virtual_midi_receiver -- --ignored --nocapture`; on Windows set `SOUNDCRAFT_LOOPBACK_IN` and `SOUNDCRAFT_LOOPBACK_OUT`. [Acceptance evidence](https://github.com/storytold/soundcraft/pull/1669#issuecomment-7072496268)

## Known limits

Calibration is manual and keyed by port name. Shared WASAPI recovery waits for stopped transport and fresh timestamps; exhausted attempts leave manual Reconnect available. Heavy worker starvation can interrupt clock delivery. OS-timestamped sends, Windows MIDI Services and MMC are deferred.

## Open questions

- Should automatic output recovery be extended to exclusive backends once fresh presentation timing and a safe backend-specific reopen procedure can be verified?
- On a stopped locate, send SPP immediately or on the next nonzero start?
- After an output timestamp gap, is evenly repaying all owed F8s within one quarter note suitable for tick-counting devices? MIDI and the Pro Tools guide leave this case unspecified.
- How should two identically named ports receive separate calibration? Keep the ±250 ms offset limit?
- Show timing warnings with zero destinations? Keep the Notes/Controllers compensation preference visible until external track output is available?
- Should live plug-in delay changes realign differently from other session revisions? Is the observed 0.337 ms per 1,000 dense-map locates material?
- When one sync preference is malformed, should recovery reset only that field?
