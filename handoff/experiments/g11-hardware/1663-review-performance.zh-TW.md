# G-11 MTC 審查後的 Windows 驗證

PR #1663 原始實機版為 e27e3f1。修正程式為 1894632，cb584c0 再調整測試的雙聲道取樣寫法。使用者於本輪未操作設備。

| 檢查 | 本次結果 |
| --- | --- |
| 29.97 ND，一小時偏移，定位 01:00:10:00 | 原版 307,200 samples，修正後 480,480 samples，即 10.010 秒 |
| 23.976 與 30 fps | 定位及起播使用正確的工作階段速率；產生器與接收器在四種輸出格式的軟體迴路誤差均不超過 1 sample |
| 大緩衝區／DAC 延遲 | 模擬後端 30 ms 延遲，驗證兩個音訊區塊的 QF 時戳連續且包含輸出提前量 |
| 失去時間碼、錄音 | 已鎖定時無 UI 更新仍能校速及跟停。切入錄音釋放追蹤用音高處理延遲 |
| 5 秒定位、起音與同步 | 合成音與模擬後端，首音保留，第二音間隔 0.497 秒，17 秒檢查點晚 90 samples（1.875 ms），失去時間碼後停止 |
| 音高 | 套回審查探針的舊接合法會重現 G4 偏差 9.426 音分；原本雙側分別計速的實作通過 2 音分門檻 |
| 測試 | 單支 PR 50 DSP、126 playback、351 UI。Windows 整合 50 DSP、136 playback、352 UI |
| 實體迴路 | 原始實測起音間隔 0.50273 秒、17 秒晚 2.86 ms。修正版尚待相同專案及接線重測 |

## 效能量測

Windows 最佳化測試執行檔以相同量測程式做三輪原版／新版交錯比對。空專案用 64 與 2048 幀緩衝、每批 16 次回呼，去除暖機批次。MIDI 輸出走原生工作執行緒，以程序內接收器記時，模擬提前 30 ms 排程，每個幀率每輪 360 筆 QF。下表為三輪中位數。

| 指標 | 原版 | 修正版 |
| --- | ---: | ---: |
| 64 幀回呼，產生器開／關 | 1.819／1.756 µs | 1.950／1.844 µs |
| 2048 幀回呼，產生器開／關 | 47.675／47.325 µs | 50.838／49.825 µs |
| 24／30 fps 傳送延遲 P95 | 1.684／1.471 ms | 1.680／1.472 ms |
| 24／30 fps 間距絕對誤差 P95 | 1.617／1.143 ms | 1.610／0.872 ms |

2048 幀開啟產生器時增加約 3.16 µs，關閉時也增加約 2.50 µs。各輪受 Windows 排程影響，有一輪 2048 幀耗時明顯偏高。結果不能推算大型音軌專案的 CPU、待機耗電或實體埠延遲。輸出執行緒活躍時以 1 ms、閒置時以 10 ms 為輪詢等待上限。

## 晚間實機複驗

沿用 Model 12 MIDI OUT → UM‑ONE → SoundCraft 與原 S-MU2000 專案。在 5.000 秒定位，播放至約 22 秒，停止後回錄 4 秒。重新檢查第一音 A4、到 F♯5 約 0.50 秒、第 17 秒誤差在 10 ms 內、無提早補播及停後多觸發，並依既有波形對齊方法比對音高。另以可對時的音訊及 MIDI 擷取檢查產生器的實際 DAC 對位。
