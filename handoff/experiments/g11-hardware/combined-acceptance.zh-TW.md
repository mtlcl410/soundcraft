# G-11 本機驗收與實機重測清單

這一版分成三層。Beat Clock 輸出提供時間排程與共用的 MIDI 埠。MTC 產生及追隨使用該排程，加入帶時間戳的輸入與估算器。外部 MIDI Clock 跟隨使用同一個輸入時基，控制速度與播放狀態。

## 第三輪審查與可重現結果

- #1662。舊版收到 50 次輸入通知時，輸出執行緒跑了 660 圈。修正版同時涵蓋已設定輸出與未設定輸出兩種狀態。更換 Beat Clock 目的地也會保留其他埠的校正值。
- #1663。Session Setup 的 Freewheel、Jam Sync 經存檔、重開與切換專案驗證。六種速率都能保留一小時起點。輸入早於起點的時間碼時，腳本與畫面會指出起點；外部輸入會保留游標，回到範圍後能重新鎖定。已重現並修正 UI 收到 Roll 之前解除 Online 的競態。模擬一小時、驅動時鐘慢 100 ppm 時，最大映射誤差從 360 ms 降到 0.30 ms；快 100 ppm 時為 0.20 ms。實機測試同步保存 arrival_delay_p95_us。
- #1669。兩小時模擬輸入 388,800 個脈衝，舊版把先前的小節移動了 125 samples；修正後歷史拍點維持原位，接受 530 次速度更新，最大相位誤差 3.42 ms。128 軌、4,096 個片段的合成專案中，更新播放快照的 p95 從 1,792 µs 降到 19 µs。保留已錄製的速度變化所需空間仍隨實際變化數增加。

## 回家後的實機驗收

三支草稿定案後再做以下實機測試。這次的電腦內部測試沒有量到 USB、五針 DIN、外部合成器或重負載音訊圖的端到端延遲。舊版錄音屬於先前的演算法。

| 項目 | 接線與操作 | 記錄 |
|---|---|---|
| Beat Clock 輸出 | SoundCraft 輸出經 Model 12 和 UM-ONE 擷取。在 120、180 BPM 各從零點和非格線位置播放，再停止。 | 120 與 180 BPM、−200 samples 校正前後的差異、首個 F8 對齊、SPP／Continue 次序、停止後的脈衝。 |
| MTC 輸出與停止定位 | 使用同一條迴路，測 24、25、29.97 DF 和 30 fps；另測 23.976 及 29.97 non-drop 的實際速率。| Quarter-frame 的間距、停止定位的完整標籤；29.97 DF 在一般分鐘跳過 00、01，第十分鐘保留 00、01。 |
| 單一輸出埠 | 讓 Beat Clock 和 MTC 同時送到同一個 MIDI OUT，分別測啟用與停用。 | 只開一次連線；兩種訊息均正確，停用一項後另一項繼續。|
| 追隨 Model 12 | 本體錄音機 MIDI OUT → UM-ONE；確認 session start 與本體時間碼相符，停止時定位，播放、停止，再測短暫中斷、Freewheel、Jam Sync 和錄音拒絕。| 首音、鎖定／定位、Freewheel 8 frames 與 Jam Sync 拔線、持續偏移後重新定位、失去時碼後的行為；記錄 `setup.midi_sync_status`。 |
| 重負載 | 重複輸出與追隨，48 kHz、64／256／1024 frames，比較空閒與約 70% DSP、視窗顯示與最小化。| 記錄音訊緩衝、埠校正、輸出 lead、傳送延遲、重新定位、裝置回呼空檔和過期訊息數。|
| 外部 MIDI Clock 跟隨 | Model 12 當時鐘主機，從 DIN 經 UM-ONE 接收。測 Start／Stop、裝置有送出的 Continue／SPP，以及中斷後的行為。若有可變速主機，另測播放中調速。 | BPM 讀值、相位誤差、鎖定與恢復、錄音位置；檢查儲存後原本的速度圖。|

三支 PR 分別列出 Windows 軟體驗證結果及待做的實機驗收。合併順序是 #1536 → #1662 → #1663 → #1669（外部 MIDI Clock 跟隨）。
