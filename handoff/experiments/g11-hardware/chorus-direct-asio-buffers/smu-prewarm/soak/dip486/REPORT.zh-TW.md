# 64 取樣在 486.242 秒的 MAIN 掉音

原始 MAIN 回錄在這個位置多出 **107 個近乎靜音的取樣，合計 2.426 ms**。先前報告的 1.45 ms 是掃描視窗覆蓋的 64 個取樣。移除完整的 107 個取樣後，前後波形正好接回 SoundCraft 交給 ASIO 9/10 的相鄰兩個取樣。這解釋了為什麼聽感上可能出現短暫中斷，同時數位輸出裡仍保有完整的音符。

![原始 MAIN 波形以及同一事件附近的回呼間隔](main-gap-and-callback.png)

## 還原原始事件

- 逐樣本比對原本的兩路浮點擷取。以舊偵測視窗第一個取樣為 0，MAIN 的近靜音區從 −43 延伸到 +63。MAIN 在 −44 對應到輸出 +63，MAIN 在 +64 對應到輸出 +64。將前後兩側分別與 ASIO 輸出對齊，雙聲道殘差 RMS 為 0.95 個 16 位元 PCM 單位。靜音區 RMS 為 0.61，前後各 64 個取樣分別為 190.44、212.77。輸入和輸出擷取序號在附近都連續。[逐樣本資料](original.json) · [接合與殘差](splices.json)
- 在輸出回呼 #335528 與 #335529，兩次**開始處理音訊**相隔 6.518 ms。前一個區塊的實測工作耗時 0.419 ms，前一段計時結束到下一段開始相隔 **6.099 ms**，下一塊的工作耗時 0.400 ms。44.1 kHz／64 取樣的預算是 1.451 ms。輸入端與輸出端的擷取時間戳也同步出現 6.498、6.497 ms 的間隔，其後四個輸出區塊接連在約 0.38–0.45 ms 的起始間隔內交付。這些時間由計時探針的終點時間戳減去區塊耗時回推，量到的是 SoundCraft 音訊處理段的起迄。
- 在先前 **128 取樣長播**的同一段伴奏，以三段波形定位同一個樂音，再以該次 ASIO 輸出對齊該次 MAIN。對應 64 取樣視窗的預期與實收 RMS 為 202.99、203.14，沒有該段近靜音。兩次長播各自跟隨實體 MIDI Clock，因此比較採用樂音對齊。[兩組原始計時與波形數據](original.json)

## 獨立 ASIO 重播

從原始 64 取樣的 ASIO 9/10 擷取取出含事件的 32,768 個取樣。獨立 PortAudio ASIO 客戶端直接送相同 PCM 至 Model 12 的 9/10，同時收 MAIN USB 11/12。只有片段最外側各 128 個取樣做淡入、淡出，事件位置距離兩端均約 16,384 個取樣。兩組均核對原廠驅動實收區塊大小及重播素材雜湊。

每一組正常重播四次，另交錯四次在指定區塊送出前刻意等待，以模擬來不及交付資料的情形。64 取樣實測交付間隔 6.57–6.99 ms，128 取樣 6.57–6.92 ms。這個干預能測試「同樣的 PCM 晚交付是否足以出現這種波形」，無法回推原始事件中是哪個執行緒延誤。[實機重播程式](replay.py) · [64 原始重播與計時](replay-64.npz) · [128 原始重播與計時](replay-128.npz)

| 實測 | 64 取樣 | 128 取樣 |
|---|---:|---:|
| 正常交付，檢出相同形式的近靜音插入 | 0 / 4 | 0 / 4 |
| 刻意延遲交付，檢出近靜音插入 | 3 / 4 | 2 / 4 |
| 四次延遲分別插入的取樣數 | 127、43、0、35 | 18、0、0、35 |
| 最長插入時間 | 2.88 ms | 0.79 ms |

兩側各自比對同一份輸出，再以取樣位移和靜音段重建接點。重播中辨認出的五處插入，移除後前後波形都恢復連續，殘差 RMS 均低於 1 個 PCM 單位。已用位置與長度已知的人工插入訊號驗證分析。即使出現這些插入，獨立客戶端的 PortAudio 回呼狀態旗標也全為零。128 取樣受干預時最長的 35 個取樣，短於前輪長播採用的 64 取樣掉音判讀視窗。[對齊結果](splices.json) · [分析程式](splice.py)

**歸因。** 晚交付足以在這台機器的 ASIO → Model 12 → MAIN 回錄路徑產生同型缺口。原事件的長間隔位於兩次 SoundCraft 區塊處理之間；沒有足夠證據指向混音、S‑MU2000 或 MIDI Clock 排程的程式缺陷。原始長播沒有核心排程、USB 匯流排追蹤或獨立類比輸出錄音，無法把責任細分到 Windows 排程、驅動、裝置播放或 USB 回錄。這輪的變更限於本機驗收與量測。

## 原專案的兩個起播點

另用 SoundCraft、同一個預熱版 S‑MU2000、原始八小節專案，以及 Model 12 DIN OUT → UM‑ONE 的實體 MIDI 迴路做 12 次新驗收。

| Model 12 MAIN 起播結果 | 64 取樣 | 128 取樣 |
|---|---:|---:|
| 8.000 秒，銅鈸只響一次 | 4 / 4 | 4 / 4 |
| 8.125 秒，沒有補播銅鈸 | 2 / 2 | 2 / 2 |
| 後續伴奏的最低樣本相關值 | 0.99245 | 0.99177 |

ASIO 輸出與 MAIN 的銅鈸計數一致；每次均實收 SPP、Continue、144 個 Clock 和 Stop，兩路擷取序號均連續。新短播無符合 64 取樣衰減門檻的視窗；其中一次 64 取樣起播仍見局部波形殘差。聽感待本人回家盲聽。測畢已確認原廠面板恢復 256 取樣。[逐次 MIDI 與 MAIN 驗收](../../music-dip486-check64.json) · [兩路波形與版本核對](verification.json)


補做 64 與 128 取樣各 9 分鐘的同步排程、DPC、USB 與音訊擷取。最長回呼外空檔分別為 2.1298、3.5393 ms。兩輪都未重現第 486.242 秒的 107 取樣插入。逐次核對 64 取樣的 8 次超時，在第 13.498 秒附近的 MAIN 找到另一處 40 取樣（0.907 ms）的近靜音插入，接點在 #37504 開頭。同段 ASIO 輸出與 128 取樣對照連續。64 取樣最長一次有 2.0841 ms 在等待，0.0044 ms 在等 CPU，期間 Model 12 播放端點完成兩筆傳輸。詳見[回呼空檔實機驗收](../etw-gap/REPORT.zh-TW.md)。
