# SoundCraft 閒置時自動恢復 ASIO 回呼

本機驗收使用 upstream main `85623f28`、獨立修正 `28da1ffa`。Model 12 需要 packed I24，實機版 `eee6a79b` 額外合入 #1634 `a89e9a4e`，未合入 G-11。#769 處理 ASIO 輸入開關時的死鎖，#807 涉及 ASIO 主機／裝置的共用，#1634 提供取樣格式與錄音輸入支援。現有搜尋結果中未找到針對持續慢回呼的修正。[main + I24 對照](ASIO-storage-main-I24.zh-TW.md) · [獨立 ASIO 播放器重建對照](ASIO-storage-reopen.zh-TW.md)

## 回歸與修正

在修正前，將實機八個連續的間隔（250.779 至 251.436 ms）對應到舊版持續前進的 block 計數。停止時既有看門狗不要求重建，回歸斷言失敗。新版在驅動每次要求輸出時量測實際間隔。連續四個間隔同時達到 100 ms 及上一個 buffer 名義週期的八倍，才標記為持續變慢。短暫卡頓或合法的大 buffer 不會單獨觸發。測試也覆蓋播放、錄音、待處理走帶指令和重試期限。[紅測原始紀錄](asio-cadence-red.log) · [Windows 播放模組測試](asio-cadence-green.log)

當走帶與錄音均已停止，由 UI 執行緒釋放雙向串流，依原裝置 ID、格式、取樣率與緩衝重建；保留既有混音、外掛、走帶和 MIDI 狀態。原裝置暫時無法開啟時，保持原路由並間隔重試。已進入錯誤狀態的音訊引擎有獨立的錯誤處理。

## Model 12 實機

設定沿用 Model 12 1.50 0103、TASCAM Model Mixer ASIO、48 kHz／256 取樣。每窗約 8 秒，以原生 ASIO buffer switch 的 Windows 效能計數器計時，每次重新建立雙向緩衝時分檔。恢復要求平均間隔在 5.333 ms 的 ±5%、至少 1,400 個間隔、沒有 240–260 ms 間隔，另核對裝置取樣位置與回呼序號。前兩輪預定在播放中跨越 STORAGE，退出後先量慢串流，再只下 Stop；第三輪預定全程先保持停止。每輪在恢復後以同一個專案播放 A4，核對輸出與回送。此測試量的是回呼節奏。

操作員離席前未進入 STORAGE，此份資料僅為進 STORAGE 前的實機對照。11 月 23 日的三輪完整量測另列於下。[執行與原始資料](runs/storage-soundcraft-idle-02/)

儀器校準時，分析器把奈秒乘上 QPC 頻率後才除以十億，64 位元整數溢位造成空視窗。修正換算後，同一段原始檔有 1,499 個間隔，全部在 4 至 <7 ms。此校準只包含基準，未執行 STORAGE，不計入三輪。

## 已完成的實機對照

正式產品測試版在同一個雙向串流上，停止時 1,499 個間隔全部在 4 至 <7 ms，平均 5.33355 ms。正常錄放時 1,500 個間隔全部在相同區間，平均 5.33331 ms，兩窗的裝置取樣位置與回呼序號均連續。只錄電腦回送的第 9 輸入。存下的 48 kHz 單聲道 WAV 有 384,256 個取樣（8.0053 秒），其中 A4 與已知波形相關係數大於 0.99999。兩窗均使用原始串流，沒有重建。

## 診斷版的自動恢復測試

診斷版 `56dbdbc5` 只在偵測器入口注入連續間隔 251 ms 的時間戳。Model 12 的原生回呼仍正常；由未改動的產品恢復邏輯實際關閉及重建雙向串流，全程同一程序，未使用 Reconnect。每次恢復後，以已載入的同一段 A4 檢查 ASIO 輸出 1 與輸入 9，兩路對參考波形的相關係數都大於 0.99999。

| 注入時的狀態 | 注入期間 | 停止後 | 恢復後八秒內平均間隔 |
|---|---|---|---:|
| 已停止 | 自動重建一次 | 維持停止 | 5.33349 ms |
| 播放中 | 連續觀察 6 秒，仍在播放，串流未更換 | 自動重建一次 | 5.33288 ms |
| 錄音中 | 連續觀察 6 秒，錄音持續，串流未更換 | 完成錄音後自動重建一次 | 5.33284 ms |

三個恢復後的視窗各有 1,499 個相鄰間隔，全在 4 至 <7 ms，沒有裝置取樣位置或回呼序號跳號。錄音存下 312,832 個取樣（6.5173 秒），檔內 A4 與參考波形相符。正式修正未包含時間戳注入功能。舊 main 另用真實時間間隔重播八次，2.01 秒後同一斷言失敗；修正提交的 Windows ASIO 播放模組 108 項通過。

## 發布判定

以 main 為目標可獨立提報「ASIO 持續慢回呼時，停止走帶及錄音後自動恢復」。獨立 SDK 已能重現慢回呼並靠重建恢復；未分離驅動、韌體與 Windows 之間的影響。11 月 23 日三次真實進出 STORAGE 均通過。錄音中延後恢復的驗證仍採用診斷版注入；這三輪涵蓋播放及停止。尚未推送或建立公開 Issue／PR。
