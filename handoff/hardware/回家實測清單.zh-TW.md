# Model 12 回家後的集中驗收

**2026-11-23 已完成全部面板操作。** [三次本體跟播](本體三次跟播-20261123.zh-TW.md) · [三次 STORAGE](ASIO-storage-idle-recovery.zh-TW.md)

本輪需要面板操作的項目是三次本體跟播和三次 STORAGE。十組 DIN 和兩項獨立對照都已完成，詳細結果見 [實體 DIN](H4a-候選版實體DIN.zh-TW.md)。Windows 曾於量測中重新啟動；先確認測試機穩定再開始本表。在同一次到場完成，不用另建歌曲、錄音、彈琴或更換接線。等電腦顯示擷取就緒再開始。

| 階段 | 操作者在 Model 12 做什麼 | 電腦記錄與判定 |
|---|---|---|
| 1　準備 | 從本機操作，確認韌體 1.50 0103、歌曲 040209_0002、48/24、本體停止。原有兩條 DIN 和 USB 保留。CH9/10 維持 PC，監聽低音量。CLOCK/SPP 關，OUTPUT DELAY 為 DISABLE。 | 驗證端點、ASIO 實際回報 48 kHz／256、測試版 SHA-256 及非遠端狀態。前端有 USB Fs mismatch 時先對齊取樣率。 |
| 2　三次本體跟播 | MIDI TIMECODE 開。解除錄音待命。前兩次從 0:00 播到約 1:10 再停；第三次從 0:30 播到約 1:40 再停。每次停止後等至少 3 秒。最後將 MIDI TIMECODE 關閉。 | 使用本機 MTC 候選，記下每次鎖定、重新定位、ASIO 輸出與 USB 回送的絕對起音時間。三次首音極差門檻 3 ms。以唯一波形核對全段，單列跳過的音。 |
| 3　三次 STORAGE | 本體停止、SD 寫完。每輪收到通知才進 MENU → STORAGE → F4（YES）。等我確認 Windows 安全退出 SD 後才退出 STORAGE，回到歌曲畫面。三次都由電腦處理 SoundCraft 的走帶。 | 使用獨立的 main 自動恢復候選。前兩次讓 SoundCraft 播放，量出舊串流後由電腦下 Stop；第三次 SoundCraft 已停止。核對是否自動恢復到 5.333 ms ±5%，8 秒至少 1,400 個間隔，裝置取樣位置、回呼序號連續，原雙向路由可播放並回錄 A4。 |
| 4　結束面板操作 | 兩項 MIDI 發碼保持關閉，回到歌曲畫面並停住。保留接線，設備可留給自動量測。 | 電腦產生五種格率、兩個 DIN 方向的 MTC，每組十次；已完成者不重做。逐次核對線上封包、定位、起音、絕對延遲與組內極差。逐組要求 USB 回送極差 ≤3 ms。 |

同一份 A4 測試聲在 STORAGE 前後的輸出／回送相關係數須 >0.99，並檢查回送相對輸出的延遲變化是否在 3 ms 內。這項額外檢查量的是音訊往返。獨立的 main 修正不包含 MTC，不能用它宣稱 H-3b 的 MTC 對 A4 相位也已通過。M-1 已有兩套完整的有效基準，本輪沿用原檔。

## 電腦端執行

在本資料夾執行。每個實測階段建立帶時間的全新結果目錄。verify 只讀本機檔案。

```powershell
python home_batch.py verify
python home_batch.py recorder
python home_batch.py storage
python home_batch.py din --case 29.97nd forward
python home_batch.py din --case 29.97nd reverse
```

STORAGE 期間，先看當輪 ready 檔，再通知進入 STORAGE。安全退出必須以本輪 safe-eject 憑據確認。操作員回到歌曲畫面後，才建立同一輪的 restored 標記；每輪完成量測後再進下一輪。保留三輪原始回呼與 PCM。離線備妥的兩個版本分別是 MTC 整合版 f13949d9 和 main 自動恢復 + I24 版 eee6a79b。
