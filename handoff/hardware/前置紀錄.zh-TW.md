# 實測紀錄補充

- **手動時段**：操作員選擇測試工具就緒後於今晚做一次。開始前保持停止。硬體韌體 1.50 0103，照片確認 PC ← MULTI 與 PC CH1/2 → CH9/10，直連 USB 重插後 Windows 列出音訊、MIDI 與 UM-ONE。
- **英文 fallback**：#1662 移除了 30 行 pt-BR 手工翻譯。#1663 合併下層後，目錄掃描測試在 `Offset (samples)` 失敗，已照同一套 fallback 規則修正測試，merge 到 #1669。最新三支 PR 的格式檢查通過，針對性的測試分別為 16、16、17 項，遠端 CI 等候核准。實機證據放在本機及 PR 留言。
- **M-1 測法**：每個緩衝都重建 ASIO 串流 20 次；每次送出六個不同的短碼，以波形相關峰定位。每組都核對實際 ASIO sample position 和序號，篩掉漏掉回呼的量測。程式自報延遲的差額一律以實測減回報計算。
- **排除紀錄**：第一次 128 路由檢查缺少分析套件，未播出；已改用現有 NumPy。同一驅動在面板偏好上限 256 時拒絕開 512，保留該次 InvalidBufferSize，另外以驅動偏好 512 開串流並查證。M-2 早期工具將 MIDI Active Sensing（FE）當成意外封包，已改成保留 FE 的原始時間戳，只計算 F8 配對。虛擬測試驗證 FE 可穿插，漏 F8 或多 F8 仍會報錯。凡環境紀錄不合格均不計入有效統計。
- **端口選擇**：一般 Model 12 MIDI 確認雙向導通，第二組 MIDIIN2／MIDIOUT2 實測沒有轉送這次的 F8。正式輪使用實際導通的端點。方向互換後重新量，沒有把往返除以二。
- **M-3 計量邊界**：SD 與 USB 音訊均由同一 Model 12 提供。兩份記錄是獨立檔案，但裝置內部可能共用時鐘。需要同時報告相對 sample 漂移與 Windows QPC 對照，避免把兩檔相符當成兩台獨立振盪器的驗證。
